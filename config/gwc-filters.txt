# Parameter filters de GeoWebCache, aplicados por scripts/init-gwc-filters.sh
# en cada `make up` y `make deploy`. Sin ellos GWC no procesa la peticion: se
# pierden el cache y el metatiling 4x4, y los poligonos que cruzan el borde de
# un tile salen cortados.
#
# Formato:  workspace:capa                 -> solo el filtro de ENV
#           workspace:capa=<valor CQL>     -> ENV + ese valor de CQL_FILTER
#
# El valor de CQL debe coincidir BYTE A BYTE con el que manda el visor. Para
# obtenerlo sin equivocarse: `scripts/init-gwc-filters.sh --learn`, que lo lee
# del trafico real del gateway, y pegar aqui lo que reporte.
#
# Una capa puede repetirse con distintos valores de CQL: se acumulan.
# Un valor no declarado se sigue sirviendo, solo que sin cache. Cada valor
# declarado multiplica el disco de geoserver_data/gwc/, asi que conviene
# declarar los de uso real y no la cola larga de fechas.
#
# El filtro de ENV va en TODAS las capas del catalogo, tengan o no `tiled`:
# el visor manda ENV=geom:geom_iieg en cada GetMap y sin el filtro declarado
# GWC responde MISS siempre. Marcar una capa como `tiled` sin esto la deja en
# ~70 peticiones por pantalla sin cache, peor que la imagen unica.
# La lista sale del catalogo:
#   SELECT DISTINCT w.geoserver_workspace || ':' || l.geoserver_layer
#   FROM mapalab.layers l JOIN mapalab.workspaces w ON w.alias = l.workspace_alias
#   WHERE l.node_type='leaf' AND l.deleted_at IS NULL AND l.disabled=false
#     AND l.geoserver_layer IS NOT NULL ORDER BY 1;
